# 03 データ定義設計

すべてのゲーム内容は `data/*.json` に置き、コードを触らずに追加・調整できるようにする。
起動時に `src/data/registry.js` が読み込み、必須項目と参照整合性（存在しないIDの参照など）を検証する。`npm run validate` で同じ検証をコマンドラインから実行できる。

共通ルール
- `id`: ASCII の snake_case。ファイル内で一意。
- `name`: 日本語の表示名。`desc`: 説明（ツールチップ）。
- `note`: 時代考証・出典・「要確認」などのメモ（ゲームには表示しない）。
- 数値のバランス調整値は各ファイル内に持つ。全体定数は `balance.json`。

## tabs.json — 建築バーのタブ
```json
{ "tabs": [ { "id": "residential", "name": "住居", "icon": "house", "color": "#3fa34d", "items": ["house_commoner", "house_shi", "house_noble"] } ] }
```
- `items` は `buildings.json` か `structures.json` の id。並び順がボタンの順。どの物も1つのタブにだけ入れる（官府など `initial` のものは除く）。
- `color` は表示モード「用途」とミニマップの色。`icon` は `src/ui/icons.js` のアイコン。

## buildings.json — プレイヤーが置き、満足度で育つ建物
```json
{
  "id": "house_commoner",
  "name": "庶民の家",
  "category": "residential",
  "tab": "residential",
  "size": [1, 1],
  "place": ["single"],
  "cost": { "qian": 20, "wood": 4 },
  "buildDays": 10,
  "requires": { "roadWithin": 3 },
  "neighbors": { "adjWorkshop": -10, "adjFarm": 5 },
  "term": "commoner",
  "levels": [
    { "level": 1, "capacity": 5, "models": ["house_c1_a", "house_c1_b", "house_c1_c"] },
    { "level": 2, "capacity": 8, "buildDays": 15, "upgrade": { "satisfaction": 65, "needs": ["water"] }, "models": ["..."] },
    { "level": 3, "capacity": 12, "buildDays": 20, "upgrade": { "satisfaction": 70, "needs": ["water", "market"] }, "models": ["..."] }
  ],
  "note": "版築の壁に茅葺き。レベル3で瓦葺き"
}
```
- `category`: residential / farm_house / field / market / workshop / military（計算の種類）。`tab`: 建築バーのタブ（`tabs.json`）。
- `size`: 向き 0（南）での [幅, 奥行き]。向き 1・3 では入れ替わる。畑は [4, 4]。
- `place`: 置き方。`single`（1つずつ・ドラッグで並べる）、`area`（範囲で埋める。畑だけ）。
- `cost`: `qian`（銭）・`wood`（木材）・`stone`（石材）。`buildDays`: 建設日数。
- `requires`: 置ける条件。`roadWithin`（足跡のどこかが道路からこのマス数以内）、`marketAdmin`（市亭の範囲）、`resource`+`radius`（近くの資源）、`field`+`radius`（近くの桑・麻の畑）、`workshopNear`+`radius`（近くの金属工房）、`nationAny`（国）、`tileNear`+`tileCount`+`radius`（近くの地形のマス数。伐木場=森、石切場=丘・山）。
- `neighbors`: 満足度の「周辺」（隣の工房・畑・宗廟・卿大夫の邸）。
- `levels[].upgrade`: 次のレベルへの条件。`satisfaction`（満足度の基準。省くと `balance.upgrade.levelUp.threshold`）と `needs`（`water` / `market` / `temple` の組み合わせ）。`levels[].buildDays` は格上げ工事の日数。
- 工房は `jobs` と `produces`（交易品）、伐木場・石切場は `jobs` と `material`（`wood` / `stone`）を持つ。畑は `crop` を持ち `crops.json` を参照（働き口はマス数 × `balance.economy.farmJobsPerTile`）。

{

## persons.json — 実在人物
```json
{
  "id": "li_mu",
  "name": "李牧",
  "nation": "zhao",
  "born": null, "died": -229,
  "appears": -247, "homeCity": "handan",
  "stats": { "lead": 96, "valor": 85, "wit": 88, "politics": 60, "charm": 75 },
  "skills": ["cavalry_master", "defender"],
  "role": "general",
  "bio": "趙の名将。匈奴を大破し、秦軍を肥・番吾で撃退。郭開の讒言で誅殺された。",
  "source": "『史記』廉頗藺相如列伝",
  "note": "要確認: 能力値は評価による相対値。生年不詳。"
}
```
- `born` が不明なら `null`、`appears` に登場開始年、`died` に没年。没年不明は `null` + `note`。
- `recruitable: false` は後ろ盾（呂不韋・春申君など。登用対象外で人材画面に表示）。`homeNation` は出身国（仕える国と違うとき）。`loyaltyBase` は忠誠の基礎値（既定 60）。
- 能力は `effectiveStats` で年齢の衰え（60歳超は年1%減、下限70%）を反映する。

## techs.json — 技術・制度
```json
{
  "id": "iron_plow", "name": "鉄製農具", "field": "agriculture", "tags": ["iron"],
  "cost": 40, "days": 180, "requires": [],
  "effects": [ { "type": "farm_yield", "value": 0.15 } ],
  "unlocks": [], "desc": "鉄の鋤・鍬で深く耕せる",
  "note": "戦国期に普及"
}
```

- `cost` は研究費（銭/月）、`days` は基準の日数。実際の速さ = (1 + 客館の research 効果 + 配下の最大知略/400) × 国の得意分野（`nations.techBonus` の field か tags が一致すれば最大値）× 技術の research_speed。
- 効果種別: farm_yield / crop_yield(crop) / irrigation_bonus / workshop_output(goods) / market_tax / tax_income / security / loyalty / build_speed / research_speed / market_range / office_slots / visitor / trade / military(branch) / diplomacy / conscription。`unlocks` は解禁する structures の id（structures 側の `unlock.tech` と対応）。
- 国の初期技術は `nations.startTechs`（前提を飛ばして最初から完成）。

## assets.json — アセット定義表（3Dモデル）

## advice.json — 案内役の助言（条件と文）
```json
{ "characters": [ { "id": "owl", "name": "ホウ", "role": "県令を見守る物知りなフクロウ", "image": "assets/ui/advisor.png" } ],
  "frequency": { "normal": { "name": "普通", "cooldownScale": 1, "minGapDays": 10 }, "off": { "name": "オフ" } },
  "advices": [ { "id": "famine", "priority": 5, "expression": "warning", "cooldownDays": 20,
                 "when": { "metric": "foodSufficiency", "lt": 0.9 }, "title": "民が飢えています", "text": "…", "todo": "食糧を確保する" } ],
  "tutorial": [ { "id": "t_road", "title": "まずは道路を", "text": "…", "done": { "metric": "roadsAdded", "gte": 4 } } ] }
```
- `when` / `done` は条件。`{ metric, lt|lte|gt|gte|eq|ne|includes|truthy }` を `all` / `any` / `not` で組み合わせる。指標名は `src/sim/advisor.js` の `computeMetrics` が返すキー（money, balance, balance3, grainMonths, loyalty, security, loyaltyDrop, vacant, waiting, jobsOpen, unemployed, abandoned, unconnected, lowSatisfaction, problemReason, problemTip, problemView, materialsWood, housesAdded, fieldsAdded, wells, month, monthStart, newUnlock, fine など）。
- `priority` 5=至急 … 1=目標。同時に成り立つ助言は優先度の高い順。`cooldownDays` は同じ助言を再び出すまでの日数（頻度設定の `cooldownScale` を掛ける）。`minGapDays` は助言全体の最短間隔。
- `expression` は `expressions` の1つ（normal / happy / troubled / warning）。文中の `{name}` は指標の値に置き換わる。
- `todo` があれば「いまやるべきこと」の一覧に出る（吹き出しが出ない間隔中でも一覧には残る）。
- `characters` は案内役の一覧（現在はフクロウ「ホウ」のみ。2人以上並べると設定に選択が出る）。先頭が既定。`name` は文中の `{name}` にも入る。`image` は右下に出す画像（透過 PNG、高さ 512px 程度）。`images` で状態（normal/happy/troubled/warning）ごとの表情の画像に差し替える（ホウは4種とも `assets/ui/advisor_*.png`。無い状態は `image`）。
- `tone.endings` は口癖: 文の終わり（。！？や末尾。「」の中は除く）が `from` で終わっていれば `to` に置き換える（上から順、最初の一致のみ）。`overrides` は助言・案内の id ごとに title/text を差し替える（自己紹介など、そのキャラ固有の文）。
- `tutorial` は初回プレイの案内。順に進み、`done` が成り立つ（または `done` がなければ表示から3日）で次へ。

## achievements.json / difficulties.json / balance.json
- achievements: `{ id, name, desc, condition: { type, value } }`
- difficulties: `{ id, name, startMoney, disasterRate, aiAggression, tributeRate }`
- balance: 時間（日/秒）、満足度の各係数（`satisfaction`）、格上げ・衰退（`upgrade`）、置き方（`placement`: 岸辺の距離・移動と修繕の費用の割合・撤去で戻る木材・元に戻す件数）、建設材料（`materials`）、人口増減率と入居待ち（`population.waiting`）、価格弾力性、戦闘係数など、設計書の数式に出る定数。開始時の材料は `start.materials`。

## セーブデータ
```json
{ "version": 2, "savedAt": "...", "seed": 12345, "cityId": "chen", "nationId": "chu", "rngState": 0,
  "day": 0, "calendar": {}, "map": { "w": 192, "h": 192, "tile": [], "height": [], "fertility": [], "resource": [] },
  "roads": [], "materials": { "wood": 200, "stone": 40 }, "buildings": [], "nextBuildingId": 1, "money": 5000, "indicators": {}, "security": 60, "foodSufficient": true, "log": [] }
```
`map.w / map.h` は必須（無い古いデータは正方形とみなす）。
建物は `{ id, buildingType, category, x, y, w, h, level, variant, rotation, state: building|built|abandoned, progress, buildDays, satisfaction, upTimer, downTimer, upgrade? }`。
`version` を上げたら `src/sim/save/serialize.js` の `migrate` に読み替えを足す。版1（区画方式）は読めない（`saveCompatibility` が理由を返す）。

## 検証ルール（`npm run validate`）
- 必須項目の存在、`id` の一意性、参照先IDの存在（tab→building/structure、building→model、city→nation など）、格上げ条件の種類。
- `models` は各建物レベルにつき3件以上。
- 禁止語チェック: `name`/`desc`/`bio` に「紙」「椅子」「茶」「綿」「仏」「寺」「火薬」「鐙」などが含まれていたら警告（誤検知は `note` に `allow:紙` と書いて除外）。
- persons: `died` が `appears` より前でないこと。
