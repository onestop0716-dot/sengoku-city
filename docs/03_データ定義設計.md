# 03 データ定義設計

すべてのゲーム内容は `data/*.json` に置き、コードを触らずに追加・調整できるようにする。
起動時に `src/data/registry.js` が読み込み、必須項目と参照整合性（存在しないIDの参照など）を検証する。`npm run validate` で同じ検証をコマンドラインから実行できる。

共通ルール
- `id`: ASCII の snake_case。ファイル内で一意。
- `name`: 日本語の表示名。`desc`: 説明（ツールチップ）。
- `note`: 時代考証・出典・「要確認」などのメモ（ゲームには表示しない）。
- 数値のバランス調整値は各ファイル内に持つ。全体定数は `balance.json`。

## persons.json — 実在人物
```json
{
  "id": "li_mu",
  "name": "李牧",
  "nation": "zhao",
  "born": null, "died": -229,
  "appears": -247, "homeCity": "handan",
  "stats": { "lead": 96, "valor": 85, "wit": 88, "politics": 60, "charm": 75 },
  "skills": ["cavalry_master", "defender"],
  "role": "general",
  "bio": "趙の名将。匈奴を大破し、秦軍を肥・番吾で撃退。郭開の讒言で誅殺された。",
  "source": "『史記』廉頗藺相如列伝",
  "note": "要確認: 能力値は評価による相対値。生年不詳。"
}
```
- `born` が不明なら `null`、`appears` に登場開始年、`died` に没年。没年不明は `null` + `note`。
- `recruitable: false` は後ろ盾（呂不韋・春申君など。登用対象外で人材画面に表示）。`homeNation` は出身国（仕える国と違うとき）。`loyaltyBase` は忠誠の基礎値（既定 60）。
- 能力は `effectiveStats` で年齢の衰え（60歳超は年1%減、下限70%）を反映する。

## offices.json — 官職
```json
{ "id": "assistant_magistrate", "name": "県丞", "minRank": "magistrate", "mainStats": ["politics"],
```

## techs.json — 技術・制度
```json
{
  "id": "iron_plow", "name": "鉄製農具", "field": "agriculture", "tags": ["iron"],
  "cost": 40, "days": 180, "requires": [],
  "effects": [ { "type": "farm_yield", "value": 0.15 } ],
  "unlocks": [], "desc": "鉄の鋤・鍬で深く耕せる",
  "note": "戦国期に普及"
}
```

- `cost` は研究費（銭/月）、`days` は基準の日数。実際の速さ = (1 + 客館の research 効果 + 配下の最大知略/400) × 国の得意分野（`nations.techBonus` の field か tags が一致すれば最大値）× 技術の research_speed。
- 効果種別: farm_yield / crop_yield(crop) / irrigation_bonus / workshop_output(goods) / market_tax / tax_income / security / loyalty / build_speed / research_speed / market_range / office_slots / visitor / trade / military(branch) / diplomacy / conscription。`unlocks` は解禁する structures の id（structures 側の `unlock.tech` と対応）。
- 国の初期技術は `nations.startTechs`（前提を飛ばして最初から完成）。

## assets.json — アセット定義表（3Dモデル）
```json
{ "id": "house_c1_a", "kind": "procedural", "generator": "houseCommoner", "params": { "roof": "thatch", "variant": 0 } }
{ "id": "granary_a", "kind": "gltf", "src": "assets/models/granary_a.glb", "scale": 1.0, "credit": "CREDITS.md#granary_a" }
```
`kind: "gltf"` が指定され読み込みに成功すればそれを使い、失敗時は `generator` にフォールバックする。

## advice.json — 案内役の助言（条件と文）
```json
{ "character": { "name": "ホウ", "role": "県令を見守る物知りなフクロウ", "image": "assets/ui/advisor.png" },
  "frequency": { "normal": { "name": "普通", "cooldownScale": 1, "minGapDays": 10 }, "off": { "name": "オフ" } },
  "advices": [ { "id": "famine", "priority": 5, "expression": "warning", "cooldownDays": 20,
                 "when": { "metric": "foodSufficiency", "lt": 0.9 }, "title": "民が飢えています", "text": "…", "todo": "食糧を確保する" } ],
  "tutorial": [ { "id": "t_road", "title": "まずは道路を", "text": "…", "done": { "metric": "roadsAdded", "gte": 4 } } ] }
```
- `when` / `done` は条件。`{ metric, lt|lte|gt|gte|eq|ne|includes|truthy }` を `all` / `any` / `not` で組み合わせる。指標名は `src/sim/advisor.js` の `computeMetrics` が返すキー（money, balance, balance3, grainMonths, loyalty, security, loyaltyDrop, demand*, zonedUnbuilt, blockerReason, wells, month, monthStart, newUnlock, fine など）。
- `priority` 5=至急 … 1=目標。同時に成り立つ助言は優先度の高い順。`cooldownDays` は同じ助言を再び出すまでの日数（頻度設定の `cooldownScale` を掛ける）。`minGapDays` は助言全体の最短間隔。
- `expression` は `expressions` の1つ（normal / happy / troubled / warning）。文中の `{name}` は指標の値に置き換わる。
- `todo` があれば「いまやるべきこと」の一覧に出る（吹き出しが出ない間隔中でも一覧には残る）。
- `character.name` は文中の `{name}` にも入る（名前はここで変更できる）。`character.image` は右下に出す画像。
- `tutorial` は初回プレイの案内。順に進み、`done` が成り立つ（または `done` がなければ表示から3日）で次へ。

## achievements.json / difficulties.json / balance.json
- achievements: `{ id, name, desc, condition: { type, value } }`
- difficulties: `{ id, name, startMoney, disasterRate, aiAggression, tributeRate }`
- balance: 時間（日/秒）、繁栄度の各係数、人口増減率、価格弾力性、戦闘係数など、設計書の数式に出る定数。

## セーブデータ
```json
{ "version": 1, "savedAt": "...", "seed": 12345, "cityId": "chen", "nationId": "chu", "rngState": 0,
  "day": 0, "calendar": {}, "map": { "w": 192, "h": 192, "tile": [], "height": [], "fertility": [], "resource": [] },
  "roads": [], "zones": [], "buildings": [], "nextBuildingId": 1, "money": 5000, "demand": {}, "security": 60, "foodSufficient": true, "log": [] }
```
`map.w / map.h` は必須（無い古いデータは正方形とみなす）。
`version` を上げたら `src/sim/save/migrations.js` に移行関数を追加する。

## 検証ルール（`npm run validate`）
- 必須項目の存在、`id` の一意性、参照先IDの存在（zone→building、building→model、city→nation など）。
- `models` は各建物レベルにつき3件以上。
- 禁止語チェック: `name`/`desc`/`bio` に「紙」「椅子」「茶」「綿」「仏」「寺」「火薬」「鐙」などが含まれていたら警告（誤検知は `note` に `allow:紙` と書いて除外）。
- persons: `died` が `appears` より前でないこと。
