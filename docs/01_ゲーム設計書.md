## 1. コンセプト

| 項目 | 内容 |
|---|---|
| ジャンル | シムシティ型の都市開発シミュレーション（3D、リアルタイム） |
| 舞台 | 中国・戦国時代後期。開始は前247年（秦王政 元年） |
| プレイヤー | 七雄のいずれかに仕える一都市の長官（県令）。王にはならない |
| 基本ループ | 区画設定 → 建物・田畑が自動で建つ → 人口増 → 税収増 → 開発・軍備・研究 |
| 出世 | 県令（一都市）→ 郡守（郡＝複数都市）→ 相邦/大将軍（国全体） |
| 終了条件 | 所属国の天下統一でエンディング。以後も継続プレイ可 |
| 三大方針 | ①時代考証に忠実 ②長く遊べる奥行き ③都市開発が常に主役 |

**都市開発が主役** とは: 戦争・外交・出世は全て「都市で作ったもの」（人口・銭・穀物・兵・城壁・人材・技術）を入力として結果が決まる、という接続方式を指す。戦闘そのものの操作は最小限。

## 3. 時間と暦

- シミュレーションは **1日＝1ティック** の固定ステップ。描画フレームとは独立。
- 速度: 一時停止 / 通常（2日/秒）/ 2倍 / 4倍。通常速度で1年≈3分。数値は `balance.json` で調整可。
- 暦: 1年＝12か月、1か月＝30日（簡略）。表示は「前247年 3月（春）」＋ツールチップに在位年（例「秦王政 元年」）。
- 季節: 春（1〜3月）夏（4〜6月）秋（7〜9月）冬（10〜12月）。
  - 春: 播種（農地の生産開始）。
  - 秋: **収穫**。農業収入（田租）と穀物がまとめて入る。桑（絹）は夏。
  - 冬: 建設速度 −50%、行軍速度 −30%、兵糧消費 +20%。
- 一時停止中も区画設定・建設指示・政策変更ができる。

## 4. マップ

### 4.1 都市マップ（メイン画面）
- 正方グリッド。標準 192×192 マス（設定で 128 / 192 / 256）。1マス＝建物1棟（庶民住居）程度。
- 地形の変化はマップの大きさに応じて増やす: 160 以上では本流が太くなり、支流（1〜2本）、湖（1〜2個）、丘の群れ、森の大きなむらが加わる。資源の数は面積に比例。
- 各マスの属性: 標高、地形種（平地 / 丘 / 山 / 川 / 湖沼 / 森 / 湿地 / 海岸）、肥沃度、水利（川・湖への距離）、資源（銅 / 鉄 / 塩 / 木材 / 粘土 / 漆）。
- 都市テンプレート（`data/cities.json`）が「立地特性」を決め、細部は毎回シード付き自動生成:
  - 例: 咸陽＝渭水沿い・平原・北に丘 / 邯鄲＝平原・西に太行山 / 臨淄＝沿海・塩 / 薊＝北方・馬・森 / 陳＝平原・水運 / 大梁＝大平原・運河（鴻溝）/ 新鄭＝丘陵・鉄。
- 初期状態: 中央に官府（県廷）と短い道路、既存の小さな里が1〜2つ。周囲は未開発。
- 開始都市は各国の候補（首都を含む）から選ぶ。

### 4.2 全国マップ（別画面）
- 史実ベースの七雄勢力図（前247年。楚の首都は陳、前241年の史実イベントで寿春へ遷都）。主要都市・交易路・関所・河川を2D（Canvas）で表示。
- ここで行うこと: 外交、貿易（商隊の派遣先）、出陣、人材の動向確認、他都市の視察（郡守以上）。
- 各国・各都市は簡略な「国力モデル」で動く（人口・兵力・富・威信）。プレイヤーの都市だけが詳細シミュレーション。

## 5. 区画（ゾーン）システム — 自動成長

### 5.1 区画の種類
| 区画 | 細分 | 建つもの |
|---|---|---|
| 住居 | 庶民 / 士 / 貴族（卿大夫） | 住居（レベル1〜3）。里（壁で囲われた居住単位）としてまとまる |
| 農地 | 粟 / 黍 / 麦 / 菽（豆）/ 稲 / 桑 / 麻 | 田畑、農家、桑園 |
| 市 | — | 市の店（市亭の管理範囲＝半径10の中でのみ建つ。人口 200 人以上で需要が出る） |
| 工房 | 青銅器 / 製鉄 / 陶器 / 織物（絹・麻）/ 漆器 / 製塩 / 車両 / 武器（弩など） | 各工房。種類は近くの資源（銅・鉄・粘土・塩、半径6）、畑（桑・麻、半径8）、国（漆器=楚・秦）、金属工房の近く（車両・武器）から自動で決まる |
| 軍営 | — | 兵舎 / 馬厩 |

- ドラッグで矩形指定。設定は無料または安価、建物が建つ時に建設費がかかる。
- 農地は地形適性（`data/crops.json`）で収量が変わる: 稲＝湿地・南方の都市で高収量、麦＝北方平地、桑＝丘陵、菽＝痩せ地でも可。

### 5.2 成長ルール
毎日、区画内の各マスについて:

1. **道路接続**（必須）: 道路から3マス以内でなければ建たない。既存建物は接続を失うと衰退。
2. **繁栄度** P（0〜100）を計算:

```
P = 50
  + 水利      (井戸・水路の範囲内 +15 / なし −20)
  + 市への距離 (住居: 市まで ≤12マス +10 / 農地: 市まで ≤20 +5)
  + 治安      ((治安−50)/5 → −10〜+10)
  + 食糧充足   (充足 +10 / 不足 −20)
  + 周辺環境   (住居: 隣接工房 −10、隣接宗廟/学宮/宮殿 +10（士・貴族）、隣接農地 +5（庶民）)
  + 需要      (該当区画の需要メーター × 0.2 → −10〜+10)
  + 官吏効果   (任命人物の政治などによる補正)
  + 肥沃度     (農地のみ: (肥沃度−0.5)×20 → −10〜+10)
  + 道路      (接続を失った建物: −100 → 繁栄度0で必ず衰退)
```
3. **レベル変化**: P ≥ 65 が 30日続けば +1（最大3）。P < 30 が 60日続けば −1。0で廃屋→撤去。
4. **新築**: 道路が届き（住居3・農地6マス以内）、需要 > 0 で、P ≥ 35（標準難易度）なら建設待ちに入り、建設費を払って着工。基本値50に水の減点（−8）が付いても 35 を上回るので、道路と需要があれば最低レベルの家は基本的に建つ。繁栄度は主にレベルの上下に効く。「難しい」では基準 50・水の減点 −20。
   建たない区画をクリックすると「建たない理由」と「助言」（井戸を近くに建てると水 +20 など）を表示する（`sim/zones.js` の `explainBuildBlockers`）。
5. **森**: 区画や道路を置いた時点で自動で伐採され平地になる（ログに「森 N マスを伐採」と出す）。
5. 里: 住居がまとまると自動で里の壁（低い版築壁）と里門が生成され、治安 +5。
6. **岸辺**: 水際から `zoning.shoreDistance`（既定1）マス以内には区画を置けない（砂地として表示）。
7. **建物の向き**（`sim/placement.js`、見た目の規則）: 入口（門）は ①接する道路側 ②複数なら通りが長い側（近い道路を優先、2マス先まで） ③道路がなければ南（坐北朝南）。向きは90度単位。同点なら南→東→西→北。建て替え（レベル変化）時に見直す。特殊建築も原則南向き。

### 5.3 需要メーター（RCI相当）
住居 / 農 / 商 / 工 の4本を −100〜+100 で表示。

| 需要 | 主な増加要因 | 主な減少要因 |
|---|---|---|
| 住居 | 空き仕事、民忠高、食糧充足、威信 | 空き家、民忠低、治安低 |
| 農 | 人口あたり穀物不足、穀物価格高 | 穀物余剰 |
| 商 | 人口増、交易路、特産品 | 市の空き店舗、関税高 |
| 工 | 資源あり、軍需（徴兵・武庫）、交易需要 | 原料不足、工人不足 |

### 5.4 城と郭
- 城壁（特殊建築）で囲った内側が「内城」。官府・宮殿・宗廟・武庫は内城でのみ効果最大。
- 外側の「郭」は住居・市・工房。郭にも外郭壁を築ける（維持費大）。
- 守城戦では内城・外郭の二段階で防衛する。

実装上の規則（フェーズ3）:
- 官府は開始時に中央（十字路の北側、南向き）に1つ置かれ、撤去できない。
- 線状の建築（城壁・水路・堤防・橋）はドラッグで L 字に引く。城壁が道路を横切る所は自動で城門になる（城門の費用）。橋は両端が陸で間に水がある直線のみ（9マスまで）。水路は川・湖・既存の水路につながる所から引く。堤防は岸辺のみ。関所は道路の上。船着場は水辺に接して置く。
- 城門・橋は完成すると道路として通れる。自動で置いた城門や道路上の建築を撤去しても道路は残る。
- 効果は建築が変わったときにまとめて再計算する（`services`）: 水の供給範囲、市の管理範囲、市までの距離、灌漑、治安・衛生（住居が範囲に入っている割合で都市全体に効く）、民忠、穀倉容量、守備力、内城（外周から城壁・城門以外を塗りつぶして届かない陸）。
- 学宮/客館は技術「賓客の招致」（フェーズ4）、宗廟と宮殿は郡守（フェーズ5）で解禁。武庫・練兵場・烽火台は置けるが効果はフェーズ6、伝舎・関所・船着場の交易効果はフェーズ5。

## 7. 経済・税制

- **通貨は銭のみ**。国別の交換比率は扱わない。
- **穀物は備蓄物資**。単位は石。住民の食糧と兵糧に消費。
- 税目（各 0〜30% スライダー、初期値 10%）:

| 税目 | 課税対象 | 高税率の副作用 |
|---|---|---|
| 田租 | 農地の収穫額（秋に一括） | 農民の民忠↓、流出 |
| 口賦 | 人口（毎月） | 全住民の民忠↓、反乱 |
| 市租 | 市の取引額（毎月） | 商需要↓、商人流出 |
| 関税 | 関所を通る交易額 | 交易量↓、他国友好度↓ |

- **難易度**（`data/difficulties.json`）: 「標準」が基準。「易しい」は資金 15,000・建設基準 25・水の減点 −4・俸禄 10。「難しい」は以前の値（資金 5,000・建設基準 50・水の減点 −20・俸禄 40・失業の重み 30・空き家の減点 80）。難易度はバランス定数の上書き（深いマージ）で実現し、`createRegistry(raw, { difficulty })` で適用する。セーブに難易度を含む。
- **開始時の村**（`balance.start.village`）: 庶民の家 6、粟の畑 12、農家 2、井戸 1、住民 40 人を中央の十字路の周りに置く。
- **穀物の流れ**: 収穫 → 民間の穀物（住民が消費）。「積穀率」スライダー（0〜30%）の分だけ官の穀倉へ入る（民忠に軽い負担）。穀倉は兵糧・救荒（民間の穀物が尽きたとき自動で放出。「救荒」で切替）・災害備えに使う。余剰は市で売って銭にできる（糶、フェーズ3以降）。穀倉の容量は県廷の基本分（800石）+ 穀倉建築。穀物は毎月わずかに目減りする。
- **収穫**: 各作物の収穫月の月初に、完成した畑ごとに 収量 = 基本収量 × 地形 × 気候 × 都市の適性 × 肥沃度 × レベル係数(1/1.5/2) × 働き手の充足。桑・麻は穀物でなく産物の価値（銭相当）。田租 = （穀物×穀価 + 産物価値）× 税率。
- **人口の増減（月次）**: 身分ごとに住居の収容数へ向かう。流入 = 空き × 流入率 × 魅力（民忠と食糧）、自然増 0.15%/月、民忠 35 未満または飢饉（充足 0.7 未満）で 2.5%/月 流出、住居不足なら超過分の半分が流出。
- **民忠（月次）**: 目標 = 64 − 口賦率×120 − 田租率×60 + 食糧(+10/−25) − 失業率×8 + (治安−50)×0.2 + 建築の補正 へ 20%/月 で近づく（既定の税率・食糧十分なら約 56）。25 未満で流出。治安の目標 = 55 − 失業率×15 − 人口/1000×2 + 士×0.02 + 建築の補正。流入 = 空き × 0.2 × 魅力（(民忠−30)/50、飢饉時は×0.3）。衛生 = 70 − 人口/500×4（井戸・水路はフェーズ3）。
- **支出**: 建設費、特殊建築の維持費、官吏・将兵の俸禄、軍事費（徴兵・鍛錬・出陣）、研究費、上納（国への納付。官位と都市規模で毎年決まり、滞納で王の信任↓）。
- **財政画面**: 月次の収支内訳（税目別・支出項目別）と、24か月分の推移グラフ。
- 赤字が続くと俸禄未払い→官吏・兵の忠誠↓→治安↓。

## 8. 人口・住民

### 8.1 身分
| 身分 | 住居 | 仕事 | 主な不満要因 |
|---|---|---|---|
| 農民 | 庶民住居 | 農地 | 田租高、飢饉、徴兵過多 |
| 工人 | 庶民住居 | 工房 | 原料不足、市がない |
| 商人 | 庶民/士住居 | 市 | 市租・関税高、治安低 |
| 士 | 士住居 | 官吏・軍の下級指揮・学宮 | 学宮なし、登用されない |
| 貴族（卿大夫） | 貴族住居 | 高官 | 宗廟・宮殿なし、威信低 |
| 兵 | 兵舎 | 軍営 | 俸禄未払い、練度低いまま出陣 |

- 人口は数値（例 12,340人）。住居レベルと数で上限が決まる。
- 増減: 自然増（小）、流入（住居空き × 民忠 × 食糧 × 威信）、流出（民忠低・飢饉・戦災）。
- 指標: 人口、民忠、治安、食糧充足率、衛生（井戸・水路・人口密度・獄・市の清掃で決まる。低いと疫病確率↑）。

### 8.2 住民と乗り物の表示（活気）

**住民のモデル**（`render/models/people.js`、`render/people-view.js`）: 頭・胴・両腕・両手・両脚・持ち物の部品を関節（首・腰・肩・股）で回す。近景（品質「高」で 50 マス以内）は関節つき、遠景は1部品の簡易モデル。服装は身分別: 庶民は短衣と袴に頭巾か髷、商人は深衣に頭巾、士・官吏は深衣に冠と竹簡、卿大夫は袖広の深衣に高い冠、兵は短衣に革甲・革の冠・戈。女性（髻と簪）、子供（小さい）、老人（前かがみ）を混ぜ、体格 ±5%、服の色は身分ごとの候補から選ぶ。歩行は脚と腕を逆位相で振り、畑に着いた農民は鍬を振る「作業」、商人・官吏は「会話」、それ以外は「待機」の動きをする。

実装（`render/agents-view.js`、表示専用でロジックに影響しない）: 2秒ごとに人口の 1/8（上限は品質設定）まで住民を補充し、家の前の道路から仕事場（農民→畑、工人→工房、商人→市、士・貴族→官府、兵→兵舎から巡回）まで道路を幅優先探索で歩き、しばらく滞在して戻る。牛車は畑→穀倉、荷車は工房→市、馬車は士・貴族の邸→官府、舟は船着場の間を水面づたいに往復する。カメラから 140 マス以上離れた住民は描かない。
- 表示人数は上限（初期 300体、設定で変更）。人口の数値とは切り離す。
- 各表示住民は「身分」を持ち、道路グラフ上を目的地へ歩く: 農民→畑、商人→市、工人→工房、兵→巡回、士→官府・学宮。時刻で行動が変わる（朝出勤・夕帰宅）。
- 乗り物: 牛車（農地→穀倉・市）、荷車（工房→市）、馬車（官吏・貴族）、舟（船着場間・川）。商隊は全国マップ上を実際に移動し、都市到着時に都市マップにも現れる。

## 11. 貿易・外交

### 11.1 貿易
- 交易品（`data/goods.json`）: 塩・鉄・絹・馬・漆・銅・木材・穀物・麻布・陶器・武器。
- 各都市に需給があり価格が変動（基準価格 × 需給比）。
- 商隊: 派遣先と積荷を決めて出発。全国マップ上を交易路に沿って移動（日数）。関所で関税。盗賊イベントで損失。到着で売買、帰還で銭。
- 官位が上がると派遣先が広がる（県令: 隣接都市 / 郡守: 自国全域 / 相邦: 全国）。

### 11.2 外交（標準レベル）
- 国同士の友好度（−100〜+100）。行動: 使者派遣（贈物）、同盟、不可侵、合従（対秦連合）/ 連衡（秦との個別同盟）、質子の交換、宣戦、講和。
- 県令は「王の命令」を受ける側。郡守で提案権、相邦で決定権。
- AI国は国力・友好度・史実傾向で行動。史実イベント（任意ON）が外交を揺らす。

## 12. 軍事

### 12.1 徴兵と鍛錬
- 徴兵: 人口から一定率を兵にする（農民が減り農業生産↓）。兵舎の収容数が上限。
- 兵種: 歩兵・弩兵・騎兵（馬が必要）・戦車兵（車両工房が必要）。
- 練度（0〜100）: 練兵場で毎月上昇（費用）。将軍の統率で加速。出陣で経験値。
- 装備品質: 武庫の容量と武器工房・製鉄の生産で決まる。
- 将軍の育成: 出陣・勝利で能力が少し上がる。

### 12.2 簡易戦術バトル
- 出陣前に決める: 兵種構成、将軍、陣形（『孫臏兵法』十陣より: 方陣 / 円陣 / 錐行 / 雁行 / 鉤行）、兵糧の積載量。
- 戦闘は自動。3Dで観戦（俯瞰、速度変更、退却指示のみ）。
- 種類: 野戦 / 攻城戦 / 守城戦。
- 判定（ラウンド制、`src/sim/military/battle.js`）:
```
戦力 = 兵数 × (0.5 + 練度/100) × 装備係数 × 将軍係数 × 陣形相性 × 兵糧係数 × 士気
攻城: 守備側に 城壁レベル・城門・望楼・穀物備蓄 による防御係数、攻撃側は攻城兵器で軽減
```
- 守城戦は自分の都市マップ上で行われ、**自分が築いた城壁・城門・望楼・穀倉の備蓄が直接効く**。城壁が破られると郭→内城の順に戦う。
- 結果: 領土（都市の所属変更）、人口（戦災）、人材（捕虜・登用）、威信、功績。

## 13. ランダムイベント

`data/events.json` で定義。種類: 災害（洪水・旱魃・蝗害・疫病・飢饉・地震）、社会（反乱・流民流入・盗賊）、来訪（諸子百家＝儒・法・墨・兵・縦横・農・陰陽）、政治（王命・他国侵攻・政変）、史実イベント（任意ON、年で発火。例: 前246 鄭国渠着工、前241 楚の寿春遷都、前238 嫪毐の乱）。
- 発火条件（季節、地形、指標、年）、選択肢、効果、備えによる軽減（穀倉→飢饉、堤防/水路→洪水、治安→盗賊、衛生→疫病）。
- 難易度で頻度と被害を調整。

## 14. 出世と勝利

| 官位 | 管理範囲 | 昇進条件（例） | 解禁 |
|---|---|---|---|
| 県令 | 一都市 | — | 基本操作 |
| 郡守 | 郡（自都市 + AI運営都市 2〜4） | 功績 ≥ 1000、人口 ≥ 1万、上納滞納なし | 他都市の政策指示、宗廟・宮殿、外交提案 |
| 相邦 | 国全体（文官ルート） | 功績 ≥ 5000、王の信任 ≥ 80 | 外交決定、国の予算、全都市 |
| 大将軍 | 国全体（武官ルート） | 功績 ≥ 5000、戦功 ≥ 3勝 | 国の全軍指揮、出陣先の決定 |

- 功績は「人口増・税収・技術・勝利・王命達成」で加算。相邦と大将軍は同時に片方のみ。
- **勝利**: 所属国が七雄の全首都を支配。エンディング後は継続プレイ可。
- **敗北**: 所属国の滅亡（首都陥落）。亡命して他国で続けられる（難易度による）。

## 15. セーブ・難易度・実績・チュートリアル

- セーブ: `localStorage` に 5 スロット + オートセーブ（毎年）。JSON をファイルとして書き出し/読み込み。`{"version": 1, ...}` でバージョン管理、旧版は移行関数で読み込む。直列化（`sim/save/serialize.js`）は実装済みで、マップの大きさ（w, h）を含む。大きさが無い古いデータは正方形として読み替える。スロット UI はフェーズ7。
- 難易度: 易/普通/難。初期資金、災害頻度、他国の攻撃性、上納額に差。
- 実績（`data/achievements.json`）: 人口1万 / 10万、各官位への昇進、初勝利、天下統一、全技術研究、10年無災害 など。
- チュートリアル: 初回起動時、吹き出しで「道路を引く → 住居区画 → 農地 → 井戸 → 市亭と市 → 税率」を順に案内。スキップ可。

## 17. 描画方針（Three.js）

- ローポリ・暖色系（黄土・木・瓦の灰）。夜はない（時刻は影の角度だけ）。頂点色は sRGB→リニア変換して指定色どおりに見せる。
- **地形**: マスの高さを角格子に平均→ぼかし→双三次補間した連続の高さ場（`render/terrain-field.js`）。1マスを品質に応じて 4/2/1 分割し、法線は高さ場の微分から求めて滑らかにする。色は頂点色で、草（肥沃度）→土（傾斜）→岩（急斜面・標高）、森・湿地・砂地・道路をぼかしたマスクで混ぜる。
- **水**: ぼかした水マスクで地形を水面下へ掘り下げ、別の水面メッシュ（頂点ごとの深さ属性 + シェーダー: 深さで色と透明度、正弦波の揺らぎ、ハイライト、フレネルで空の色）を重ねる。
- **区画表示**: マスごとに地形に沿った半透明の面（ぼかしなし）と、外周に細い濃色の縁取り。区画が変わるたびに作り直す。
- **色の輪郭**: 森・湿地・道路・岸辺は「頂点が属するマスの平均」で細かい格子に写し（境界幅は 1/S マス）、1セルだけぼかす。砂地は岸辺のマスと水面近くの低い土地、川底は水面下の高さで決める（標高ベースなので岸線と一致）。水の形（掘り下げ）だけはマス単位で2回ぼかして曲線にする。
- **チャンク**: 地形・区画表示・水面は 32 マス四方のチャンクごとに別メッシュ（視界外は自動で描画省略、更新は該当チャンクだけ）。分割数は品質と大きさから決め、頂点数がおよそ60万を超えないようにする（256 マスでは高品質でも3分割）。
- **多数の建物**: 近景（詳細）に入れる数に上限（高 900 / 中 600 / 低 300、木は 1500 / 900 / 400）。超えた分は近い順に選び、残りは遠景の簡略モデル。遠景の木は約40三角形。
- **マップ外**: 端の高さを引き継いでゆるやかな丘へつなぐ大地（マップ幅の2.5倍まで、格子はマップ幅/48）と、川の出口を十数マスだけ続ける水面。高い所は土・岩の色にして端の山が続いて見える。空のドームはカメラ中心に置き、背景色も地平の色にする。ズームアウト上限はマップ幅の1.35倍、霞はその1.4〜3.4倍の距離。
- **建物**: 面取り箱、反りのある瓦屋根（切妻・寄棟、瓦の縦筋）、基壇・柱・戸・窓。
- **樹木**: 松・柏・槐・楡・柳（水辺）の5種 × 2 バリエーション、回転体で滑らかな法線、大きさと向きをばらつかせる。
- **光**: 平行光源のソフトシャドウ（注視点に追従）、半球光、ACES トーンマッピング、空のグラデーション、霞。
- **品質設定**: 高（4分割・影2048）/ 中（2分割・影1024）/ 低（分割なし・影なし）。localStorage に保存し、その場で切替。
- **InstancedMesh**: 同じモデルIDの建物・木・住民をまとめて描画。
- **LOD**: モデルごとに 近景（詳細）/ 遠景（樹木は簡略生成、建物は外形の箱）の2つの InstancedMesh を持ち、カメラが動いたときに距離で振り分ける。遠すぎる木は描かない。
- **地形**: 1枚のハイトマップメッシュ + 頂点カラー。川・湖は別平面。
- **バリエーション**: 各建物タイプ × レベルにつき最低3種のモデルを `models/` で生成（屋根形状・向き・付属物・色味）。配置時にシードから決定し、再現性あり。
- **アセット差替**: `data/assets.json` に `{ id, kind: "procedural" | "gltf", src, scale, variants }`。glTF が指定されていればそれを、無ければコード生成を使う。
- 住民・乗り物の表示上限、影の有無、LOD距離は設定で変更可。

## 18. アーキテクチャ

```
data/*.json ──▶ DataRegistry（読み込み・検証）
                    │
UI (DOM) ──command──▶ Sim（純ロジック、1日=1tick、シード乱数）──state/events──▶ Render (Three.js)
   ▲                                                                     │
   └──────────────────── snapshot / events ◀─────────────────────────────┘
```

- **Sim** は `World` オブジェクト（プレーンなデータ）を持ち、`tick(world)` で1日進める。DOM / Three.js を import しない。Node で単体実行・テスト可能。
- **ループ**: 1フレームに進める日数の上限を tick の所要時間で変える（重いときは1日ずつ）。上部バーに fps と tick 時間を表示。
- **変更通知**: Sim は `world.dirty`（tiles / buildings / trees）に変更を記録し、Render が毎フレーム読んで反映・クリアする。
- **Command**: UI → Sim は `{type:"zone.set", rect, zoneId}` のようなコマンドのみ。Sim が検証して適用。
- **Event bus**: Sim → Render/UI は `building.built`, `population.changed`, `event.fired` などのイベント。描画はイベントと毎フレームの状態参照で更新。
- **決定性**: 同じシード + 同じコマンド列 → 同じ結果。テストとバグ再現に使う。
- **セーブ** = `World` の JSON 直列化（描画状態は含めない）。
- **全国マップ Sim** は `World.nation` 以下に置き、月1回の粗いティックで動く。

## 19. テスト方針

- `tests/` に `node --test`。対象: 地形生成の再現性、道路接続判定、繁栄度・レベル変化、経済の収支、暦、人口増減、研究、戦闘判定、イベント発火、セーブの往復（保存→読込で同一）、データ検証（全 JSON の必須項目・参照整合性・時代考証禁止語チェック）。
